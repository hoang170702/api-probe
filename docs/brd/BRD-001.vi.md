# CurlCase — Tài liệu thiết kế (v0.1)

> **Đối tượng đọc:** Claude Code CLI (để implement) và developer review.
> **Trạng thái:** Draft. Tên "CurlCase" là đề xuất, chưa chốt.
> **Quy ước cho người implement (Claude Code CLI):** đọc hết tài liệu trước khi code. Mục **§3 Open decisions** chưa được chốt, **không tự quyết**, hãy hỏi user trước khi bắt đầu Step 1. Làm theo từng step ở **§17**, xong mỗi step thì dừng lại, báo cáo (Done / Changed / Verification / Next) và hỏi user có tiếp tục không.

## 1. Mục tiêu

Tool giúp **tester** kiểm thử một API bằng nhiều bộ dữ liệu mà không cần viết code:

1. Tester dán một lệnh `curl` (ví dụ copy từ Postman / Chrome DevTools).
2. Tool tách ra method, URL, headers, body và **liệt kê các field** trong JSON body.
3. Với mỗi field, tester chọn **Required** hoặc **Unrequired** (dropdown).
4. Tester nhập **N bộ test case data** (bảng trên UI hoặc import CSV).
5. Tool **bắn** từng bộ, mỗi bộ chạy trên **1 goroutine/thread** qua worker pool có giới hạn.
6. Trả kết quả **realtime** cho tester: `SUCCESS` / `FAILED` / `EXCEPTION` / `BLOCKED`.
7. Tester **xuất báo cáo** Excel hoặc PDF.

### Ngoài phạm vi (v1)

- Không có database. Mọi dữ liệu của một lần chạy (run) nằm trong bộ nhớ và hết hạn sau TTL.
- Không Kafka, Redis, microservices, không đăng nhập/user management.
- Không phải công cụ load test. Concurrency bị giới hạn có chủ đích.
- Không retry tự động (xem §10.2, lý do an toàn với API payment).
- v1 chỉ hỗ trợ body **JSON**. `form-urlencoded`, `multipart`, file upload để sau.

## 2. Các quyết định đã chốt

| # | Quyết định |
|---|------------|
| D1 | Input là lệnh `curl`. BE parse ra method, URL, headers, body. |
| D2 | JSON body được flatten thành danh sách field path dạng `data.account.id`, mảng dạng `items[0].sku`. |
| D3 | Mỗi field có dropdown **Required / Unrequired**. Mặc định: `Required`. |
| D4 | Bộ test nào **bỏ trống field Required** → **BLOCKED, không bắn**, hiện cảnh báo: *"Field `data.amount` là Required, hãy nhập giá trị hoặc đổi sang Unrequired"*. |
| D5 | Field **Unrequired** bỏ trống → **xoá field đó khỏi request** (không gửi key). |
| D6 | Mỗi bộ test chạy trên 1 goroutine (Go) / 1 virtual thread (Java), qua **worker pool giới hạn N**, mỗi request có **timeout**. |
| D7 | Kết quả phân loại: `SUCCESS`, `FAILED`, `EXCEPTION`, `BLOCKED`. |
| D8 | Kết quả đẩy realtime về FE qua **SSE** (server → client một chiều). |
| D9 | **Không DB.** Run lưu in-memory có TTL. Reload trang / restart server là mất kết quả, nên tester phải xuất file. |
| D10 | Xuất báo cáo **Excel (.xlsx)** và **PDF**. |
| D11 | FE cho **export/import cấu hình** (curl + rule + test data) dạng file JSON để dùng lại lần sau. Việc này làm hoàn toàn ở FE, BE không lưu. |
| D12 | FE: **React + TypeScript + Vite + Ant Design**. BE: một monolith duy nhất. |

## 3. Open decisions (CHƯA CHỐT, phải hỏi user)

### OD1. Ngôn ngữ BE: Go hay Java?

| | **Go (đề xuất)** | **Java 21 + Spring Boot 3** |
|---|---|---|
| Mô hình "1 bộ = 1 thread" | goroutine + worker pool bằng channel/`errgroup` | Virtual Threads (`Executors.newVirtualThreadPerTaskExecutor()`) + `Semaphore` |
| HTTP server | `net/http` (Go 1.22+ có routing theo method) hoặc `chi` | Spring MVC (`spring-boot-starter-web`) |
| HTTP client | `net/http` `Client` + `context.WithTimeout` | `java.net.http.HttpClient` |
| SSE | tự viết bằng `http.Flusher` (~30 dòng) | `SseEmitter` |
| Parse JSON giữ thứ tự & kiểu số | `encoding/json` + `UseNumber()` | Jackson (`ObjectMapper`, `JsonNode`) |
| Excel | `github.com/xuri/excelize/v2` | Apache POI (`poi-ooxml`) |
| PDF | `github.com/go-pdf/fpdf` hoặc `github.com/johnfercher/maroto/v2` | OpenPDF |
| Tách curl | tự viết tokenizer (§6) | tự viết tokenizer (§6) |
| Đóng gói | 1 binary tĩnh, có thể nhúng FE build bằng `embed` | 1 fat jar, FE build đặt trong `static/` |

**Đề xuất Go**, vì: chạy nhẹ, ra 1 binary dễ phát cho tester, mô hình goroutine khớp tự nhiên với yêu cầu, và đúng hướng học Go hiện tại. **Java** là lựa chọn an toàn nếu ưu tiên tốc độ code nhờ kinh nghiệm Spring Boot lâu năm.

Phần còn lại của tài liệu viết theo Go. Nếu chọn Java, giữ nguyên thiết kế, chỉ đổi thư viện theo bảng trên và cấu trúc thư mục ở §13.2.

### OD2. Tiêu chí SUCCESS: chỉ status code hay cả body?

**Đề xuất:**
- Mỗi test case có cột `expectedStatus` (tùy chọn). Để trống thì mặc định **2xx là đạt**.
- Thêm assertion body **tùy chọn** dạng cột `expect:<jsonPath>`, ví dụ `expect:code = "00"`, `expect:data.status = "SUCCESS"`. v1 chỉ hỗ trợ so sánh **bằng** (equals) trên giá trị leaf.
- Không có cột `expect:*` nào thì chỉ so status.

User cần chốt: (a) chỉ status, (b) status + `expect:*` như trên, hay (c) cách khác.

### OD3. Tên tool

"CurlCase" (module `curlcase`) là đề xuất. Chờ user xác nhận trước khi tạo repo/module.

### OD4. Các điểm nhỏ (đã có đề xuất mặc định, cần user OK)

| Điểm | Đề xuất mặc định |
|---|---|
| Tester muốn gửi **cố ý** chuỗi rỗng hoặc `null` (khác với "bỏ trống") | Token đặc biệt: `<EMPTY>` → `""`, `<NULL>` → `null`. Ô trống thật = "không nhập". |
| Có cho tester sửa **header / query param** theo từng bộ không? | v1: **chỉ field trong JSON body**. Header và query giữ nguyên như curl. |
| Concurrency mặc định / tối đa | mặc định **5**, tối đa **20** (config được) |
| Timeout mỗi request | mặc định **30s**, tester chỉnh được trong khoảng 1–120s |
| Số bộ test tối đa mỗi run | **1000** |
| Allowlist host đích (chống bắn nhầm production) | Config `CURLCASE_ALLOWED_HOSTS`. Rỗng = cho phép tất cả (chỉ dùng local). Xem §12. |

## 5. Luồng nghiệp vụ end-to-end

```
Tester dán curl
   ↓
[1] POST /api/parse → CurlParser → {method, url, headers, bodyTemplate}
   ↓                 lỗi cú pháp → 400 + message chỉ rõ vị trí
[2] FieldExtractor flatten body → [{path, type, sampleValue}]
   ↓
[3] FE hiển thị bảng field, tester chọn Required/Unrequired (mặc định Required)
   ↓
[4] Tester nhập N case (bảng hoặc CSV): caseName, giá trị từng field,
    expectedStatus (tuỳ chọn), expect:<path> (tuỳ chọn, nếu OD2 chốt)
   ↓
[5] FE có thể pre-validate để báo sớm, nhưng BE là nguồn sự thật
   ↓
[6] POST /api/runs → BE validate từng case:
       - Required bỏ trống → BLOCKED (không bắn)
       - giá trị không ép được về kiểu của field → BLOCKED
       - hợp lệ → build request
    trả về {runId} ngay (202), việc bắn chạy nền
   ↓
[7] FE mở SSE GET /api/runs/{runId}/events
   ↓
[8] Worker pool bắn các case hợp lệ (tối đa N song song, timeout mỗi request)
   ↓
[9] Mỗi case xong → classify → lưu RunStore → đẩy SSE event "case"
   ↓
[10] Tất cả xong → SSE event "done" kèm summary
   ↓
[11] Tester bấm Xuất → GET /api/runs/{runId}/export?format=xlsx|pdf
```

## 6. Curl Parser (đặc tả)

### 6.1 Input

Chuỗi text lệnh curl, có thể nhiều dòng. Phải hỗ trợ cả hai kiểu copy phổ biến:
- **bash**: nối dòng bằng `\` + newline, chuỗi trong `'...'` hoặc `"..."`.
- **Windows cmd** (Chrome "Copy as cURL (cmd)"): nối dòng bằng `^` + newline, escape `^"`. v1 nên hỗ trợ; nếu phức tạp thì trả lỗi rõ ràng *"Hãy dùng 'Copy as cURL (bash)'"*.

### 6.2 Tokenizer

Tự viết tokenizer kiểu shell đơn giản (không thực thi shell, không expand `$VAR`):
- Bỏ `\`+newline (bash) hoặc `^`+newline (cmd).
- Trong `'...'`: giữ nguyên tuyệt đối.
- Trong `"..."`: xử lý escape `\"`, `\\`.
- Ngoài quote: tách theo whitespace.
- Token đầu phải là `curl`, nếu không → lỗi.

### 6.3 Flag hỗ trợ

| Flag | Xử lý |
|---|---|
| `-X`, `--request` | method |
| `-H`, `--header` | header `Name: value` (giữ thứ tự, cho phép trùng tên) |
| `-d`, `--data`, `--data-raw`, `--data-binary`, `--data-ascii` | body. Nhiều `-d` → nối bằng `&` (giống curl). Nếu bắt đầu bằng `@` (đọc file) → lỗi "không hỗ trợ" |
| `--json` | body + tự thêm `Content-Type`/`Accept: application/json` |
| `--url` hoặc token không phải flag | URL |
| `-u`, `--user` | chuyển thành header `Authorization: Basic ...` |
| `-k`, `--insecure` | ghi nhận `insecure=true`, xem §12 |
| `--compressed`, `-L`, `--location`, `-s`, `-v`, `-i` | bỏ qua (cảnh báo nhẹ trong `warnings[]`) |
| Flag lạ khác | không fail; đưa vào `warnings[]` |

Quy tắc method: có `-X` thì dùng `-X`; không có `-X` mà có body thì `POST`; còn lại là `GET`.

### 6.4 Output

```json
{
  "method": "POST",
  "url": "https://uat-api.example.com/v1/transfers?channel=MB",
  "headers": [
    {"name": "Content-Type", "value": "application/json"},
    {"name": "Authorization", "value": "Bearer eyJ..."}
  ],
  "bodyRaw": "{\"data\":{\"amount\":100000,...}}",
  "bodyKind": "json",
  "insecure": false,
  "warnings": ["Bỏ qua flag --compressed"]
}
```

`bodyKind`: `none` | `json` | `unsupported`. Body có nhưng không parse được JSON → `unsupported`, FE hiển thị *"v1 chỉ hỗ trợ JSON body"* và không cho chạy.

## 7. Field Extractor (flatten JSON)

### 7.1 Quy tắc

- Chỉ liệt kê **leaf** (string, number, boolean, null). Object/array rỗng cũng coi như leaf (type `object`/`array`) để tester biết nó tồn tại.
- Path: object dùng `.`, mảng dùng `[i]`. Ví dụ `data.account.id`, `items[0].sku`.
- Key chứa `.` hoặc `[` → escape bằng `["key.with.dot"]`. (Hiếm, nhưng phải không làm sai path.)
- Giữ **thứ tự key** như trong body gốc (Go: không decode vào `map`, phải đọc bằng `json.Decoder.Token()` hoặc dùng thư viện giữ thứ tự; Java: Jackson `JsonNode` giữ thứ tự sẵn).
- Number: giữ nguyên dạng chữ (`json.Number` / `BigDecimal`), **không** chuyển sang float64 (số tiền và số tài khoản dài sẽ mất chính xác).

### 7.2 Ví dụ

Body:
```json
{
  "requestId": "REQ001",
  "data": {
    "amount": 100000,
    "account": {"id": "0123456789", "type": "SAVING"},
    "note": "test",
    "urgent": false
  },
  "items": [{"sku": "A1", "qty": 2}]
}
```

Output:
| path | type | sampleValue |
|---|---|---|
| `requestId` | string | `REQ001` |
| `data.amount` | number | `100000` |
| `data.account.id` | string | `0123456789` |
| `data.account.type` | string | `SAVING` |
| `data.note` | string | `test` |
| `data.urgent` | boolean | `false` |
| `items[0].sku` | string | `A1` |
| `items[0].qty` | number | `2` |

## 8. Validator

Chạy ở BE cho **từng case** trước khi bắn. Một case có thể có **nhiều lỗi**, gom hết lại rồi báo một lần.

Quy ước giá trị ô (cell) do tester nhập, luôn là chuỗi:
- `""` (trống) = **không nhập**.
- `<EMPTY>` = gửi chuỗi rỗng `""` (theo OD4).
- `<NULL>` = gửi `null` (theo OD4).
- Còn lại = giá trị cần ép về kiểu của field.

| Điều kiện | Kết quả |
|---|---|
| Field **Required** + ô trống | lỗi `REQUIRED_MISSING`: *"Field `data.amount` là Required, hãy nhập giá trị hoặc đổi sang Unrequired"* |
| Field **Unrequired** + ô trống | hợp lệ, field sẽ bị **xoá** khỏi request |
| type `number` mà giá trị không phải số hợp lệ | lỗi `TYPE_MISMATCH`: *"Field `data.amount` cần kiểu number, nhận 'abc'"* |
| type `boolean` mà không phải `true`/`false` | lỗi `TYPE_MISMATCH` |
| type `string` | luôn hợp lệ |
| `<NULL>` | hợp lệ với mọi type (tester cố ý test null) |
| `expectedStatus` không phải số 100–599 | lỗi `INVALID_EXPECTATION` |

Có lỗi → case thành **BLOCKED**, ghi `errors[]`, **không bắn**.

> Ghi chú: muốn test API có validate "thiếu field" không thì tester đổi field đó sang **Unrequired** rồi để trống. Request sẽ không có field đó, kèm `expectedStatus = 400`.

## 9. Request Builder

Với mỗi case hợp lệ:

1. **Deep clone** body template (không được sửa template dùng chung giữa các goroutine).
2. Với mỗi field:
   - có giá trị → set vào path, đúng kiểu (`number` ghi dạng số JSON, không bọc quote).
   - Unrequired + trống → **xoá key** khỏi object cha.
     - Nếu path nằm trong mảng (`items[0].sku`) → xoá key `sku` trong phần tử đó, **không** xoá phần tử mảng.
     - Object cha trở thành rỗng → giữ `{}` (không xoá dây chuyền lên trên).
3. Serialize lại JSON, giữ thứ tự key gốc.
4. Method, URL, headers giữ nguyên như curl. Tính lại `Content-Length` (HTTP client tự làm, không copy header `Content-Length` từ curl).

Lưu `requestBody` đã build vào kết quả để tester đối chiếu trong báo cáo.

## 10. Runner (worker pool)

### 10.1 Mô hình (Go)

```
POST /api/runs
   ↓
tạo Run{status: RUNNING}, lưu RunStore, trả 202 {runId}
   ↓
go runner.Execute(ctx, run)        // ctx gắn với run, không gắn với HTTP request
   ↓
sem := make(chan struct{}, concurrency)
for mỗi case hợp lệ:
    sem <- struct{}{}               // chặn khi đủ N goroutine đang chạy
    go func(c) {
        defer func(){ <-sem }()
        defer recover()             // panic trong 1 case không được làm sập cả run
        reqCtx, cancel := context.WithTimeout(ctx, timeout)
        defer cancel()
        result := send(reqCtx, c)
        result = classify(result)
        run.Save(result)            // có mutex
        broker.Publish(runId, result)
    }(c)
wait tất cả → run.status = DONE → publish "done"
```

Có thể dùng `golang.org/x/sync/errgroup` với `SetLimit(n)` thay cho semaphore tự viết, nhưng **không** để lỗi của một case cancel các case khác (lỗi case là dữ liệu kết quả, không phải lỗi của group).

### 10.2 Quy tắc bắt buộc

- **Không retry.** API payment/transfer có thể đã commit dù client timeout. Retry có thể tạo giao dịch trùng. Timeout ghi nhận là `EXCEPTION` với `errorType = TIMEOUT`, ghi chú *"Không xác định được server đã xử lý hay chưa"*.
- Dùng **một** `http.Client` dùng chung cho toàn app (connection pool), không tạo client mới mỗi request. `CheckRedirect` trả `http.ErrUseLastResponse` (không tự follow redirect, để tester thấy 3xx).
- Đọc response body tối đa **1 MB** (`io.LimitReader`), phần dư cắt và đánh dấu `truncated=true`.
- Luôn `resp.Body.Close()`.
- Đo `durationMs` từ lúc gửi tới lúc đọc xong body.
- Thứ tự hoàn thành **không** theo thứ tự case. Mỗi kết quả mang `caseIndex` để FE và báo cáo sắp xếp lại.
- Hỗ trợ **huỷ run**: `POST /api/runs/{id}/cancel` → cancel `ctx` của run. Case chưa chạy → `CANCELLED`, case đang chạy → `EXCEPTION` (`errorType = CANCELLED`).

### 10.3 Java (nếu OD1 chọn Java)

`ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()` + `Semaphore(concurrency)` để giới hạn. `HttpClient` dùng chung, `HttpRequest.timeout(...)`, `followRedirects(NEVER)`. Không dùng `@Async` mặc định của Spring.

## 11. Result Classifier

| Status | Điều kiện |
|---|---|
| `BLOCKED` | Validator báo lỗi, case không được bắn |
| `EXCEPTION` | Không nhận được HTTP response hợp lệ: timeout, connection refused, DNS lỗi, TLS lỗi, bị huỷ. **Hoặc** đã có assertion body (`expect:*`) nhưng response không parse được JSON |
| `FAILED` | Có HTTP response nhưng status code sai kỳ vọng, **hoặc** một assertion `expect:*` không khớp |
| `SUCCESS` | Status đúng kỳ vọng (`expectedStatus`, hoặc 2xx nếu trống) **và** mọi assertion `expect:*` khớp |
| `CANCELLED` | Run bị huỷ trước khi case được bắn |

Thứ tự kiểm tra: BLOCKED → EXCEPTION → so status → so body.

Mỗi kết quả có `reason` dễ đọc cho tester, ví dụ:
- `"Kỳ vọng HTTP 200, nhận 400"`
- `"expect:code kỳ vọng \"00\", nhận \"99\""`
- `"Timeout sau 30s. Không xác định được server đã xử lý hay chưa"`
- `"Không kết nối được tới uat-api.example.com:443 (connection refused)"`

`errorType` cho EXCEPTION: `TIMEOUT` | `CONNECTION` | `DNS` | `TLS` | `INVALID_RESPONSE` | `CANCELLED` | `INTERNAL`.

So sánh `expect:<path>` (nếu OD2 chốt): lấy giá trị leaf ở `path` trong response JSON, chuyển về chuỗi để so với giá trị tester nhập. Riêng number thì so theo giá trị số (`100000` == `100000.0`). Path không tồn tại → FAILED, *"expect:data.status: không tìm thấy field trong response"*.

## 12. An toàn & bảo mật

Tool này gửi request tới URL tuỳ ý theo input, nên phải có rào chắn:

1. **Allowlist host**: env `CURLCASE_ALLOWED_HOSTS` (vd `localhost,*.uat.example.com,10.10.*`). Host không khớp → `POST /api/runs` trả 400 *"Host không nằm trong allowlist"*. Rỗng = cho phép tất cả, và log cảnh báo lúc khởi động.
2. **Giới hạn**: concurrency tối đa, số case tối đa, timeout tối đa (OD4). BE luôn kẹp (clamp) giá trị FE gửi lên.
3. **`-k/--insecure`**: chỉ bỏ verify TLS khi env `CURLCASE_ALLOW_INSECURE=true`. Nếu không thì báo lỗi rõ ràng. Mặc định dùng system trust store. Môi trường công ty có CA nội bộ thì cài CA vào trust store, không tắt verify.
4. **Masking**: trong log server và **trong báo cáo xuất ra**, mask giá trị header `Authorization`, `Cookie`, `X-Api-Key` và header chứa `token`/`secret`, chỉ giữ 6 ký tự đầu + `***`. Trên UI kết quả cũng mask mặc định.
5. **Không log body** request/response ở level INFO (có thể chứa dữ liệu khách hàng). Chỉ log `runId`, `caseIndex`, status, duration.
6. Server mặc định chỉ bind `127.0.0.1`. Muốn cho cả team dùng thì cấu hình `CURLCASE_BIND`.

Lỗi chung:

### 14.2 `POST /api/parse`

Request:
```json
{ "curl": "curl -X POST 'https://...' -H 'Content-Type: application/json' -d '{...}'" }
```
Response 200:
```json
{
  "template": { "method": "POST", "url": "...", "headers": [...], "bodyRaw": "...", "bodyKind": "json", "insecure": false },
  "fields": [
    { "path": "data.amount", "type": "number", "sampleValue": "100000" }
  ],
  "warnings": []
}
```

### 14.3 `POST /api/runs`

BE stateless giữa parse và run: FE gửi lại toàn bộ template (không cần BE nhớ kết quả parse).

```json
{
  "template": { "method": "POST", "url": "...", "headers": [...], "bodyRaw": "...", "bodyKind": "json" },
  "fields": [
    { "path": "data.amount",     "type": "number", "rule": "REQUIRED" },
    { "path": "data.note",       "type": "string", "rule": "UNREQUIRED" }
  ],
  "cases": [
    {
      "name": "Chuyển tiền hợp lệ",
      "values": { "data.amount": "50000", "data.note": "" },
      "expectedStatus": 200,
      "expect": { "code": "00" }
    }
  ],
  "options": { "concurrency": 5, "timeoutMs": 30000 }
}
```
Response `202`:
```json
{ "runId": "r_8f3a...", "total": 1, "blocked": 0 }
```

### 14.4 Model kết quả

```go
type CaseStatus string // SUCCESS | FAILED | EXCEPTION | BLOCKED | CANCELLED | PENDING | RUNNING

type CaseResult struct {
    CaseIndex      int               `json:"caseIndex"`
    Name           string            `json:"name"`
    Status         CaseStatus        `json:"status"`
    Reason         string            `json:"reason"`
    Errors         []ValidationError `json:"errors,omitempty"`     // khi BLOCKED
    ErrorType      string            `json:"errorType,omitempty"`  // khi EXCEPTION
    Input          map[string]string `json:"input"`
    RequestBody    string            `json:"requestBody,omitempty"`
    ExpectedStatus *int              `json:"expectedStatus,omitempty"`
    HTTPStatus     int               `json:"httpStatus,omitempty"`
    ResponseBody   string            `json:"responseBody,omitempty"`
    Truncated      bool              `json:"truncated,omitempty"`
    Assertions     []AssertionResult `json:"assertions,omitempty"`
    StartedAt      time.Time         `json:"startedAt"`
    DurationMs     int64             `json:"durationMs"`
}

type ValidationError struct {
    Field   string `json:"field"`
    Code    string `json:"code"`    // REQUIRED_MISSING | TYPE_MISMATCH | INVALID_EXPECTATION
    Message string `json:"message"`
}

type AssertionResult struct {
    Path     string `json:"path"`
    Expected string `json:"expected"`
    Actual   string `json:"actual"`
    Passed   bool   `json:"passed"`
}

type Run struct {
    ID        string
    Status    string        // RUNNING | DONE | CANCELLED
    CreatedAt time.Time
    Template  RequestTemplate
    Fields    []FieldRule
    Results   []CaseResult  // index = caseIndex
    Summary   Summary       // đếm theo status
    mu        sync.Mutex
    cancel    context.CancelFunc
}
```

### 14.5 SSE events

```
event: snapshot      # gửi ngay khi client kết nối: toàn bộ trạng thái hiện tại
data: {"runId":"...","status":"RUNNING","results":[...],"summary":{...}}

event: case          # mỗi khi 1 case có kết quả
data: {CaseResult}

event: done
data: {"runId":"...","status":"DONE","summary":{"total":10,"success":6,"failed":2,"exception":1,"blocked":1,"cancelled":0}}
```

- Gửi `snapshot` đầu tiên giúp client kết nối muộn hoặc kết nối lại không mất dữ liệu. Không cần `Last-Event-ID`.
- Heartbeat comment `: ping` mỗi 15s để proxy (Nginx) không cắt kết nối. Header: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- Publish không được block worker: mỗi subscriber có channel buffer, đầy thì bỏ subscriber đó (client sẽ reconnect và nhận snapshot).

### 14.6 RunStore

- `map[string]*Run` + `sync.RWMutex`.
- TTL mặc định **1 giờ** sau khi run kết thúc (`CURLCASE_RUN_TTL`). Goroutine janitor dọn mỗi phút.
- Tối đa **50 run** trong bộ nhớ. Vượt thì xoá run DONE cũ nhất. Nếu tất cả đang RUNNING → `429`.
- Run hết hạn → `GET` / `export` trả `404` *"Run đã hết hạn, hãy chạy lại"*.

## 15. FE (React + TS + Vite + Ant Design)

Một màn hình wizard dùng `Steps` 4 bước. Toàn bộ state giữ trong React (`useReducer` hoặc Zustand, không cần Redux).

**Bước 1: Dán curl.** `Input.TextArea` + nút "Phân tích". Hiển thị lỗi parse và `warnings`. Có nút **Import cấu hình (.json)** để nạp lại phiên trước.

**Bước 2: Field rules.** `Table` cột: Field path | Kiểu | Giá trị mẫu | Rule (`Select` Required/Unrequired). Có nút "Tất cả Required" / "Tất cả Unrequired". Hiện method + URL + headers (mask Authorization) ở trên để tester xác nhận.

**Bước 3: Test data.** `Table` editable: mỗi dòng = 1 case. Cột: `#`, Tên case, mỗi field path 1 cột, `expectedStatus`, các cột `expect:*` (thêm động nếu OD2 chốt). Chức năng:
- Thêm dòng / nhân bản dòng (mặc định điền sampleValue) / xoá dòng.
- Import CSV: header = `name, <field paths...>, expectedStatus, expect:<path>...`. Nút **Tải CSV mẫu** sinh header đúng theo field hiện tại.
- Pre-validate ở FE: ô Required trống tô đỏ + tooltip đúng câu cảnh báo ở D4. Vẫn cho bấm Chạy (case đó sẽ BLOCKED), nhưng hiện confirm *"Có X case sẽ bị chặn, vẫn chạy?"*.
- Cấu hình run: concurrency (InputNumber 1–20), timeout (giây).
- Nút **Export cấu hình (.json)**: `{version:1, curl, fields(rules), cases, options}`.

**Bước 4: Kết quả.**
- Thanh tổng hợp: Tổng / SUCCESS (xanh) / FAILED (đỏ) / EXCEPTION (cam) / BLOCKED (xám) + `Progress`.
- `Table` sắp theo `caseIndex`, cột: #, Tên, Status (`Tag` màu), HTTP, Thời gian, Reason. Bấm dòng → `Drawer` xem input, request body, response body (pretty JSON), assertions.
- Lọc theo status.
- Nút **Huỷ run**, **Xuất Excel**, **Xuất PDF**, **Chạy lại** (giữ cấu hình).
- Cảnh báo cố định: *"Kết quả chỉ lưu tạm X phút. Hãy xuất file nếu cần giữ."*

## 18. Kiểm thử

- **Unit**: curlparse, fields, validate, classifier. Đây là nơi chứa business rule, cần test kỹ nhất.
- **Integration**: runner + `httptest.Server`; HTTP API handlers bằng `httptest.NewRecorder`.
- **Race**: luôn `go test -race ./...` cho runner, run store, sse.
- **E2E thủ công**: FE + BE + mockapi, 50 case, concurrency 5, có vài case BLOCKED/timeout.

Các case quan trọng không được bỏ sót:
1. Field Required bỏ trống → BLOCKED, **không** có request nào tới server giả (đếm hit).
2. Field Unrequired bỏ trống → request **không chứa key** đó.
3. Số lớn / số tiền giữ nguyên chính xác trong request gửi đi.
4. Timeout → EXCEPTION/TIMEOUT, **không** retry (server giả chỉ nhận đúng 1 hit).
5. Số request đồng thời không bao giờ vượt `concurrency`.
6. Panic trong 1 case không làm sập run.
7. Huỷ run giữa chừng → case chưa chạy là CANCELLED.
